# BCi 상세 설계 규격

상태: 설계 초안. 언어 판본: `bci/0.1`. 작성일: 2026-10-31. 근거: [형식 설계 명세 1.0](../../bci_dsl_latex/main.tex).

이 문서 집합은 BCi 프로그램을 파싱하고, 타입을 검사하고, 장치를 바인딩하고, 유한 자원으로 실행하고, 결과를 재생하는 데 필요한 계약을 정의한다. 구현 완료의 판정 대상은 이 전체 계약의 연결이다. 컴파일러·런타임의 실측 결과는 향후 적합성 보고서가 기록한다.

물리적 패키지 배치와 현재 코드의 범위는 [프로젝트 아키텍처](../architecture.md)가 정의한다. 논리적 구성 요소는 11개 형제 패키지에 배치하고, 각 패키지의 Rust 파일을 같은 깊이에 유지한다.

## 설계의 중심 규칙

1. 하나의 스트림 타입은 값 표현, 순서 있는 채널 스키마, 시계, 발생 규칙, 품질 어휘를 함께 가진다.
2. 데이터 레코드는 측정 구간과 가용 시각을 각각 보존한다. 계산에 사용한 상태·모델·타이머도 의존성에 속한다.
3. 단위·기준·표본률·시간 뷰 변환은 그래프 노드로 표현한다.
4. 타입이 결정된 그래프는 구성 증거를 받아 장치에 바인딩된다. 실행 시작은 해당 경로의 필수 의무가 모두 `Pass`인 상태를 요구한다.
5. 모든 순환 경로는 초기값을 가진 양의 논리 지연을 포함한다. 실행 계획은 토큰, 메모리와 종료 규칙을 함께 제공한다.
6. 모델 선택, 전처리 통계와 임계값 선택은 학습 계보에 포함된다. 예측은 시작 시 선택한 모델 버전을 끝까지 유지한다.
7. 실행 기록은 값, 품질, 세대 전이, 명령 응답과 제어 사건의 순서를 함께 복원한다.
8. BCi의 실행문은 선언형 그래프 구성에 집중한다. 일반 제어 흐름과 알고리즘은 Rust 연산자로 구현하고, BCi는 그 경계의 타입·효과·시간·자원 계약을 검사한다.

## 이번 규격의 결정 목록

| ID | 결정 | 선택 이유와 영향 |
|---|---|---|
| D01 | 독립 `.bci` 선언형 언어, Rust 호스트 구현 | 장치·시간·계보 오류를 소스 위치와 직접 연결한다. |
| D02 | 그래프 구조는 정적으로 구체화한다. 데이터별 분기는 원시 연산자로 표현한다. | 실행 자원과 순환 의존성을 컴파일 시 계산한다. |
| D03 | 유리수 표본률·단위 배율, 정수 크기, 명목 스키마를 사용한다. | 격자와 차원 비교를 정확히 수행한다. |
| D04 | 런타임 기술자와 수치 조건은 명시적인 obligation으로 남긴다. | 정적 검사와 장치 조회의 책임을 연결한다. |
| D05 | 실행 계획을 Rust 런타임이 해석한다. 커널은 정적으로 등록한 Rust 구현을 호출한다. | 동일 계획을 참조 실행기와 장치 실행기가 공유한다. |
| D06 | 시간의 기본 저장 단위는 origin 상대 정수 ns이며 격자는 유리수로 유지한다. | 반올림 오차 누적과 서로 다른 시계의 혼합을 관리한다. |
| D07 | 필수 획득·학습 기록 경로의 기본 초과 정책은 `Fault`다. 화면 표시 분기는 `DropOldest`를 명시할 수 있다. | 누락의 영향을 경로별 계약으로 표현한다. |
| D08 | 재설정은 epoch barrier와 상태 초기화를 사용한다. 상태 보존은 등록한 migration을 요구한다. | 새 스키마에서 상태의 의미를 검증한다. |
| D09 | 기록 ID는 원천 정체성, artifact ID는 내용 해시를 사용한다. | 중복 수신과 동일 내용 재사용을 구분한다. |
| D10 | 시계·지연 증거에 `Bound`와 `Estimate`를 둔다. | 정량 보장과 통계적 관측의 사용 조건을 표현한다. |
| D11 | 전체 적합성 행렬을 공통 완료 기준으로 사용한다. | 구현 작업을 구성 요소 계약 단위로 나눌 수 있다. |
| D12 | 범용 함수·조건문·반복문·재귀는 Rust 확장에 배정한다. | BCi 문법의 책임을 그래프와 도메인 계약으로 고정한다. |
| D13 | pointwise/stateful SDK와 등록 매크로를 제공한다. | 반복되는 wrapper·registry 코드를 생성하고 수치·시간 증거를 별도 검사한다. |
| D14 | 구성별 진입점 선택과 데이터별 커널 분기를 구분한다. | 정적 그래프 계획과 실행 중 상태·의존성을 명확히 유지한다. |
| D15 | 형제 crate와 평평한 Rust 파일 배치, 의존 방향 자동 검사를 사용한다. | 구조 탐색 깊이를 줄이고 공개 계약·확장 위치를 유지한다. |

## 결정이 외부 입력을 요구하는 항목

| 입력 | 소유 위치 | 해소 조건 |
|---|---|---|
| 실제 장치 모델·펌웨어·SDK·운영체제 | hardware profile instance | 조회 결과와 버전 고정 증거를 제공한다. |
| 수치 커널·BLAS·필터 계수 | operator/kernel lock | 참조 벡터와 허용오차 보고서를 제공한다. |
| CPU 배분·호출시간·전송 지연 | execution evidence | 적용 환경을 명시한 측정 또는 상한 근거를 제공한다. |
| 피험자·세션·시행 그룹과 평가 정책 | split manifest | 데이터 카탈로그의 키와 범위를 고정한다. |

이 값들은 프로그램·배포별 매개변수다. 각 문서가 타입과 판정식을 정의하고, 해당 실행의 manifest가 구체적인 값을 채운다.
